pgvector + HNSW replaces Pinecone / dedicated vector databases

Keeping vectors in a separate database creates the "hybrid search" nightmare: finding documents semantically similar to a prompt only if authored by a specific user last week means cross-referencing two systems over a network. pgvector stores vector(32) columns right next to your relational data, uses an HNSW graph index for approximate nearest-neighbours, and lets you put the relational filters (author, tag, date) into the same SQL statement.

How this demo's embeddings work

Instead of a real ML model, each document's vector is produced by a PL/pgSQL function that hashes the character trigrams of its text into 32 dimensions. Documents that share words end up close together — good enough to feel the similarity search. The exact same function is used to embed your query. 

-- HNSW index (approximate nearest neighbour, cosine distance):
CREATE INDEX idx_documents_embedding
  ON documents USING hnsw (embedding vector_cosine_ops);

-- hybrid search: semantic + relational filters in ONE statement:
WITH query AS (SELECT text_embedding(:q)::vector AS e)
SELECT d.title, 1 - (d.embedding <=> (SELECT e FROM query)) AS similarity
FROM documents d
WHERE d.author = :author            -- relational filter
  AND d.created_at >= CURRENT_DATE - :days
ORDER BY d.embedding <=> (SELECT e FROM query)
LIMIT 5;
