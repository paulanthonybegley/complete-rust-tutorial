Row Level Security replaces hand-written authz middleware

Policies attached straight to the private_notes table make Postgres the enforcement point. Every request authenticates as a user by setting app.uid on its transaction; the database then silently returns — and accepts — only that user's rows. A badly written query can never leak another tenant's data, because the filter happens below your application code.

The policies

ALTER TABLE private_notes ENABLE ROW LEVEL SECURITY;
ALTER TABLE private_notes FORCE ROW LEVEL SECURITY;

CREATE POLICY notes_select ON private_notes FOR SELECT
  USING (owner_id = current_setting('app.uid', true)::int);

CREATE POLICY notes_insert ON private_notes FOR INSERT
  WITH CHECK (owner_id = current_setting('app.uid', true)::int);

-- per request, scoped to the transaction:
SET LOCAL app.uid = <session user id>;

The app connects as a normal, non-superuser role (demo_app) so RLS actually bites. Try the spoof box: attempt to insert a note owned by another user. The WITH CHECK policy rejects the row outright.
