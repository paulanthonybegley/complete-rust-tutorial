JSONB + GIN index replaces MongoDB / NoSQL document stores

JSONB stores your JSON as a decomposed binary format at insert time (the "B" stands for Binary). Add a GIN — a generalized inverted index — and every key/value inside every document is mapped to the rows that contain it. Nested, deeply-typed queries become instant, and those documents can still JOIN relational tables in a single ACID transaction. Schema flexibility without losing integrity.

-- the classic "contains this document" query (uses the GIN index):
SELECT * FROM products
WHERE attributes @> '{"specs": {"cpu": "Apple M3"}}';

-- JSONPath query (also index-aware):
SELECT * FROM products WHERE attributes @? '$.specs.ports[*] ? (@ == "HDMI")';
