ACID + extensibility: the weapon

Before dismantling your stack, understand the foundation. Postgres is an object-relational database: it gives you rock-solid ACID transactions, and — because of how extensible it is — it can grow custom data types, arrays, geometric shapes, key/value stores and third-party extensions (PostGIS, pgvector, pg_trgm...).

ACID in one line

Every transaction is Atomic, Consistent, Isolated and Durable. When a crash happens, your user data is not corrupted and your job queue never double-pays a worker. That guarantee is exactly what makes the replacements on the other pages safe to run inside the database.

Extensible types — not just rows and columns

Native custom types Postgres ships out of the box, used in this very project:

  • JSONB — binary JSON documents (the JSONB demo)
  • vector — extension type for embeddings (the pgvector demo)
  • geography(Point, 4326) — extension type for coordinates (the PostGIS demo)
  • tsvector / tsquery — parsed text for search (the full-text demo)
  • hstore — plain key/value pairs
  • multidimensional arrays, geometric point/circle/polygon, ranges, enums, ...

Everything this app runs on — one database, one schema
