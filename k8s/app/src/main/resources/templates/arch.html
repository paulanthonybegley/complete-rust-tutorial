Kubernetes Architecture & Purpose

Two halves make the cluster move: the control plane (the brain — API server, scheduler, controller-manager, etcd) and the worker nodes (the muscles — kubelet, container runtime, kube-proxy). The magic is that the brain only ever agrees on desired state; the workers converge reality toward it.

The purpose, in one paragraph

Your kubectl apply never 'pushes a pod to a node'. It writes one line of desired state into etcd. From then on, watchers fire: the scheduler picks a node, the controller manager creates objects, the kubelet on that node starts containers — each controller pulling reality toward the manifest, forever, on its own loop.

This loop — declare → watch → reconcile — is the single idea underneath every other chapter of the video. Health checks, scaling, rollouts, self-healing: all of them are just reconciliation running on a schedule.
