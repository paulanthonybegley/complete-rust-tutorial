YAML, Manifests & API versions

A manifest is a declaration of desired state. It must satisfy three tiny rules before the API server accepts it: a valid apiVersion, a known kind, and clean 2-space indentation. Break any of them — or use a deprecated version, like apps/v1beta1 — and apply fails in exactly the way it does here.

Immediate pitfalls to try
  • Delete metadata.name: — the schema rejects it.
  • Change two spaces to one — the indentation check flags it by line number.
  • Set apiVersion: apps/v1beta1 — reintroduced old API, rejected.
API versioning rule of thumb
  • v1 — core objects (Pod, Service, ConfigMap, Secret…) stable forever.
  • apps/v1 — Deployment & ReplicaSet stable since 1.9.
  • networking.k8s.io/v1 — NetworkPolicy in its stable group.
  • v1beta1 entries are deprecated & removed — check kubectl api-versions to learn what this cluster actually serves.
