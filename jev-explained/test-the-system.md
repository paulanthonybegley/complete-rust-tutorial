# test-the-system.md — how to check the lesson system actually works

The system is only as good as its weakest input. Run this check before trusting
the plan it produces.

## 1. Trace one line back to an input
Pick any activity in the plan. Can you point at the *exact* input in
`worksheet.md` that caused it? If not, the plan ignored your answers.

## 2. The white-page test
Same idea as the fioci-demo lesson: a blank page is rarely a mystery — it's a
template reading data that doesn't exist. **A lesson that doesn't mention your
goal is that blank page.** If the plan's sections don't map to your inputs
1–9, rewrite the input, not the plan.

## 3. The effort check
Did the plan add *more* work, or *reorganize* work you already do? A system
that adds tasks instead of ordering them is a stack of papers, not a plan.

## 4. The live sweep
Run the plan once for real (a single lesson). Did the learners do the thing in
the goal? Yes → the system works. No → change the **input**, not the output.
The plan is a mirror; the mirror isn't the problem.
